對照：另一套獨立實作

這一節是什麼：同一份課程另有一套獨立完成的實作（以下稱實作 B，檔案在 impl_b/）。兩套由同一份原始教材出發，各自寫程式、各自跑結果，不共用數字。結果一致就多一次獨立驗證；結果不一致的地方，正好是值得學的判斷點。本頁其他各節是課程主線（實作 A）。

做法差異

項目主線（實作 A）實作 B
工具檢查15 項，另外確認 femwell 0.1.12 與 Meep 1.35.0 真的能解題11 項，沒有檢查 femwell 與 Meep
KLayout 位置使用者安裝位置放在專案內 tools/KLayout/，換電腦時跟著專案走
暖身無只用 Python 標準函式庫的理想 MZI 實驗（約 60 分鐘），先建立相位與分光的直覺

結果一致

MZI 測試件兩邊幾何相同：總長 509.0 µm、兩臂在 MMI 之間各 172.566 µm；正常版 DRC 0 筆、0 個圖形超出外框；8 個故障（F1–F8）各被抓到 1 次；設計區 580 × 260 µm。兩套程式寫法不同，產生的 GDS 雜湊不同，但幾何一致。

實作 B 才有、值得一起看的內容

  • 外部埠與 PDK 埠的對照：測試件的 in0（上）接 MMI 的 in2，in1 接 in1；out0 接 out2，out1 接 out1。後面每一步都會用到「上臂＝PDK in2」這個約定，在這裡先對清楚。
  • 理想 MZI 五個情境：全交叉、均分、全直通、π 相位合光、0 相位合光，以 1e-12 的容差比對解析解，5/5 通過。程式：smoke_mzi.py，結果：smoke_mzi.json。

注意埠序約定：實作 B 的暖身頁把索引 0 當作下方的埠，但它在 M0 s3 之後改成和主線一樣，索引 0＝上方（PDK in2）。兩套程式交換資料時一定要先確認這一點。
